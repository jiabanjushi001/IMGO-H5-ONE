# 导师代理角色与数据范围设计

## 目标

为后台角色增加代理模式，并在程序更新时自动创建“导师专员”角色。代理模式账号只能查看和操作其邀请关系树中的下级数据。导师可以单独配置注册后的自动客服和自动群聊；没有单独配置时继承超级管理员的全局聊天设置。

## 角色模型

`imgo_admin_role` 增加：

- `agent_mode TINYINT NOT NULL DEFAULT 0`：是否启用代理数据范围。
- `role_code VARCHAR(32) NULL`：系统预置角色稳定标识，`mentor` 表示导师专员。
- `role_code` 使用唯一索引。普通自定义角色保持 `NULL`。

启动时自动升级数据库并执行幂等预置：

- 若 `role_code=mentor` 不存在，创建名称为“导师专员”的角色。
- `agent_mode=1`。
- 默认启用除 `manage.settings` 外的全部可分配菜单权限。
- 已存在时不覆盖管理员后来调整的名称、状态、代理模式或权限。
- 导师专员可以编辑名称、状态、代理模式和菜单权限，但不能删除。

新建自定义角色时，后台表单的代理模式默认开启。已有自定义角色升级后保持 `agent_mode=0`，避免升级后意外失去全站数据范围。

固定的“超级管理员”和“普通用户”仍为只读系统角色。超级管理员不受代理数据范围约束，普通用户没有后台管理权限。

## 导师归属

邀请关系继续使用：

- `imgo_referral.parent_user_id` 保存直接邀请人。
- `imgo_referral_path` 保存所有祖先及深度。

某用户的所属导师按以下规则计算：

1. 查询该用户邀请链上的所有祖先。
2. 祖先账号必须有效，并且其当前后台角色 `agent_mode=1`、角色状态启用。
3. 选择深度最小的祖先，即距离该用户最近的导师。
4. 用户自己是导师时，其后台数据范围以自己为根，但用户自身不计入下级数据。
5. 没有导师祖先时使用全局注册配置。

因此，若只有 `wuhu1` 是导师，`wuhu2` 到 `wuhu10` 依次邀请，通过其中任何账号邀请码注册的新用户都归属 `wuhu1`。如果以后 `wuhu5` 也被设为导师，则 `wuhu5` 以下的新注册用户归属距离更近的 `wuhu5`。

角色调整即时影响导师归属和后台数据范围，不把导师 ID 冗余写入用户表。

## 导师自动客服与自动群聊设置

新增 `imgo_agent_setting`：

- `agent_user_id BIGINT PRIMARY KEY`。
- `auto_add_user JSON NULL`：`NULL` 表示继承全局 `chatInfo.autoAddUser`，JSON 表示导师覆盖配置。
- `auto_add_group JSON NULL`：`NULL` 表示继承全局 `chatInfo.autoAddGroup`，JSON 表示导师覆盖配置。
- `updated_by BIGINT NOT NULL`。
- `updated_at BIGINT NOT NULL`。

覆盖配置允许显式关闭功能。显式关闭与“继承全局关闭”是不同状态，因此必须使用可空字段，不能只存开关值。

新增 `imgo_agent_auto_state`：

- `agent_user_id BIGINT PRIMARY KEY`。
- `last_customer_user_id BIGINT NOT NULL DEFAULT 0`。
- `group_id BIGINT NOT NULL DEFAULT 0`。
- `group_num INT NOT NULL DEFAULT 1`。
- `updated_at BIGINT NOT NULL`。

导师使用覆盖配置时，客服轮换、当前自动群和群序号使用导师自己的状态行。继承全局配置时沿用现有全局 `autoTask` 状态，使“继承”与超级管理员当前行为完全一致。

成员列表中，仅导师账号显示“导师设置”操作。弹窗分别为自动客服、自动群聊提供“继承全局设置”开关：

- 开启继承时显示当前全局配置摘要，导师字段不可编辑。
- 关闭继承时可以配置开关、客服列表、欢迎语、群主、群名称和人数上限。
- 保存时后端验证客服与群主账号有效，并且所选账号属于该导师的下级范围；导师本人也可以作为客服或群主。

导师设置接口仅超级管理员可访问。

## 注册分配流程

注册事务按以下顺序执行：

1. 校验邀请码并创建用户。
2. 写入直接邀请人与完整邀请路径。
3. 从邀请路径中解析最近的有效导师。
4. 分别解析自动客服与自动群聊的有效配置：导师有覆盖值时用覆盖值，否则用全局值。
5. 若使用导师覆盖配置，锁定该导师的 `imgo_agent_auto_state`；若继承全局配置，沿用全局 `autoTask` 锁和状态。
6. 创建双向好友、欢迎消息并加入或创建自动群。
7. 与用户注册一起提交事务；任何一步失败均回滚。

通过同一导师团队内任何层级的邀请码注册，都会使用同一个导师配置和轮换状态。

## 统一代理数据范围

后端新增统一数据范围对象，基于当前登录用户返回：

- `global`：超级管理员，或代理模式关闭的授权角色。
- `agent`：代理模式开启的角色，范围根为当前用户 ID。
- `none`：普通用户，不允许访问管理接口。

代理范围使用 `EXISTS` 查询 `imgo_referral_path`，条件为 `ancestor_user_id=当前导师`。默认包含所有深度；成员页选择“直属下级”时增加 `depth=1`。

所有列表、详情和修改操作必须调用同一范围校验组件。前端隐藏数据不视为权限控制。

### 成员

- 默认查询全部下级。
- “直属下级”只查询深度 1；“全部下级”查询所有深度。
- 用户名精确或模糊搜索始终叠加在导师范围内。
- 详情、签到记录、编辑、备注、删除、状态、密码等操作均验证目标用户属于导师下级。
- 导师通过后台添加成员时，新成员自动绑定为该导师的直属下级。
- 设置后台角色仍仅超级管理员可操作。

### 概况

- 用户：下级账号。
- 群聊：群主属于下级的群。
- 消息：下级参与的私聊，或群主属于下级的群聊消息。
- 文件：上传者属于下级的文件。
- 在线用户和设备：当前在线且属于下级的账号。
- 注册、群聊、消息、文件趋势使用相同范围。

代理在线历史新增按导师记录的采样表；升级后的新样本开始形成趋势，不伪造升级前历史数据。

### 群聊

- 仅显示和操作群主属于导师下级的群。
- 转让群主、新增成员、删除成员和设置管理员时，目标用户必须是导师下级；群主也必须保持在导师范围内。

### 消息

- 私聊消息：发送者或接收者属于导师下级。
- 群聊消息：所属群的群主属于导师下级。
- 联系人、消息详情和消息处理使用相同范围。

### 文件

- 仅显示上传用户属于导师下级的文件。
- 下载与后台预览继续执行原聊天参与者权限，并叠加导师范围校验。

### 银行卡、钱包与财务

- 列表和详情按所属用户是否为导师下级过滤。
- 充值、人工入账、提现、审核和流水查询在事务开始前及锁定记录后再次验证所属用户，避免越权和竞态。

### 全站数据

代理模式不能执行以下全站操作：

- 发布、修改或删除系统公告。
- 全站消息清理。
- 定时清理任务配置。
- 系统设置。
- 角色管理与角色分配。

代理可以读取系统公告，但不能修改。

## API 与前端

角色保存接口增加 `agent_mode`。角色列表返回 `agent_mode` 和 `role_code`。

新增超级管理员接口：

- `POST /manage/agentSetting/detail`：读取导师覆盖值和全局配置摘要。
- `POST /manage/agentSetting/save`：保存两个可空覆盖配置。

成员列表“更多”菜单仅在行数据 `agent_mode=1` 时显示“导师设置”。角色列表和成员列表返回该标志。

角色页面增加“代理模式”开关，新建角色默认开启。关闭代理模式的角色仍按已有菜单权限访问全站数据，因此只有超级管理员可以修改该开关。

## 错误处理与安全

- 目标不在导师范围时统一返回业务码 `403` 和“无权操作”，不区分记录不存在与越权。
- 导师角色被禁用或取消代理模式后，下次请求立即使用新范围；角色变更继续撤销目标用户会话。
- 导师设置中的用户 ID 必须服务端重新查询和校验，不能信任前端选项。
- 数据范围条件必须进入 SQL 查询或事务内校验，不能先读取全量数据再在 Go 内过滤。
- 自动注册分配继续使用事务和数据库锁，保证并发注册不会重复选择状态或创建超过人数限制的群。

## 数据库升级

普通启动通过 `EnsureAddonSchema` 幂等完成：

- 增加角色字段与索引。
- 创建导师设置、导师状态和导师在线采样表。
- 创建或补齐导师专员预置角色及默认权限。
- 不覆盖已有自定义角色和管理员已修改的导师权限。

Linux 包更新后直接启动即可执行升级，不需要手工导入附加 SQL。数据库账号必须具有 `CREATE`、`ALTER`、`INSERT` 权限。
